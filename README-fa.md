## 🌟 نمای کلی و فلسفه طراحی

اجرای یک پروژه متن‌باز ناآشنا در حالت عادی نیازمند کلون کردن کد، رمزگشایی فایل‌های ناقص README، تطبیق نسخه‌های مختلف پایتون/نود، راه‌اندازی کانتینرهای دیتابیس، تنظیم متغیرهای محیطی `.env` و عیب‌یابی خطاهای پورت‌های اشغال‌شده است.

**ابزار RunRepo این فرایند طولانی و طاقت‌فرسا را به یک دستور کاملاً قطعی (Deterministic) تبدیل می‌کند:**

```bash
runrepo setup https://github.com/owner/project
```

### اصول بنیادین سیستم

۱. **اولویت با قطعیت (Deterministic First)**: تمامی تحلیل‌ها از طریق بررسی فایل‌های Lockfile، مانیفست‌های پکیج، درخت انتزاعی نحو (AST) و ابزارهای استاندارد انجام می‌شود و نیازی به حدس‌های احتمالی نیست.  
۲. **تفکیک دقیق فازها**: تحلیلگر مخزن (فکت‌های فقط‌خواندنی) ← بررسی محیط میزبان ← برنامه‌ریز گراف اجرایی (DAG) ← مجری ایمن ← تاییدکننده صحت اجرا ← موتور عیب‌یابی تشخیصی.  
۳. **امنیت پیش‌فرض (Safe by Default)**: عملیات پرخطر نیازمند تایید کاربر است، دستورات مخرب مسدود می‌شوند و حالت پیش‌نمایش (`--dry-run`) هیچ تغییری روی سیستم ایجاد نمی‌کند.  
۴. **تکرارپذیری تضمین‌شده**: با استفاده از `runrepo.lock` بازتولید بیت‌به‌بیت محیط‌ها در سیستم‌های مختلف بدون نشت اطلاعات حساس تضمین می‌شود.  
۵. **هوش مصنوعی صرفاً برای ابهامات**: مدل Gemini تنها به‌صورت کاملاً اختیاری برای سناریوهای با ابهام بالا یا خطاهای ناشناخته به کار گرفته می‌شود.

## 🚀 شروع به کار و نصب

### پیش‌نیازها

- **پایتون**: نسخه `>= 3.11`
- **uv**: *(پیشنهادی)* ابزار فوق‌سریع مدیریت بسته‌ها و پروژه‌های پایتون
- **داکر**: *(اختیاری)* برای بالا آوردن خودکار سرویس‌ها و پایگاه‌های داده

### نصب با استفاده از `uv` (روش پیشنهادی)

```bash
# کلون کردن مخزن پروژه
git clone https://github.com/AmirHossein-84/RunRepo.git
cd RunRepo

# نصب وابستگی‌ها و همگام‌سازی محیط مجازی
uv sync

# اجرای خط فرمان RunRepo
uv run runrepo --help
```

### نصب از طریق `pip`

```bash
pip install -e .
runrepo --help
```

## 💻 راهنمای دستورات خط فرمان (CLI)

### ۱. دستور `runrepo setup` — تحلیل، آماده‌سازی و راه‌اندازی

```bash
# راه‌اندازی مستقیم از آدرس گیت‌هاب
runrepo setup https://github.com/fastify/fastify

# راه‌اندازی پوشه محلی بدون توقف برای تاییدیه
runrepo setup ./my-project --yes

# حالت پیش‌نمایش بدون اعمال تغییرات فیزیکی (Dry-Run)
runrepo setup ./my-project --dry-run

# دریافت خروجی ساختاریافته به فرمت JSON
runrepo setup ./my-project --yes --json
```

### ۲. دستور `runrepo plan` — مشاهده گراف مراحل اجرایی

```bash
# مشاهده درخت وابستگی مراحل و سطح ریسک هر دستور
runrepo plan ./my-project
```

### ۳. دستور `runrepo doctor` — ارزیابی محیط سیستم و مخزن

```bash
# بررسی کلی ابزارها، پکیج منیجرها و داکر سیستم
runrepo doctor

# بررسی سازگاری سیستم با نیازهای یک پروژه خاص
runrepo doctor ./my-project
```

### ۴. دستور `runrepo pr` — بازتولید پول‌ریکوئست‌ها در محیط ایزوله

این دستور PRهای گیت‌هاب را بدون دستکاری کد اصلی شما، در یک پوشه کش ایزوله تست و اجرا می‌کند:

```bash
# بررسی و بازتولید PR شماره ۱۲۳
runrepo pr https://github.com/owner/repo/pull/123

# اجرای PR در حالت موقت (حذف خودکار پس از پایان کار)
runrepo pr https://github.com/owner/repo/pull/123 --ephemeral
```

### ۵. دستور `runrepo repair` — خودترمیمی و حل خودکار تعارضات

بررسی خودکار و رفع مشکلات رایج محیط محلی:

```bash
# آزادسازی پورت‌های مسدود، ساخت مجدد venv خراب، استارت داکر و تنظیم .env
runrepo repair ./my-project
```

### ۶. دستور `runrepo share` — تولید اسکریپت آنبوردینگ برای هم‌تیمی‌ها

خروجی اسکریپت‌های دفاعی بش (`setup.sh`) و پاورشل (`setup.ps1`) جهت اجرای یک‌کلیکه توسط دیگر اعضای تیم:

```bash
runrepo share ./my-project --output ./scripts
```

### ۷. دستور `runrepo export` — استخراج کانتینرهای زیرساخت

تولید فایل استاندارد و مستقل `docker-compose.yml` بر اساس نیازهای دیتابیسی کشف‌شده پروژه:

```bash
runrepo export ./my-project --output ./docker-compose.runrepo.yml
```

### ۸. دستورات `runrepo status` و `runrepo stop` — مدیریت پردازه‌ها

```bash
# مشاهده لیست سرورهای در حال اجرای مدیریت‌شده با RunRepo
runrepo status

# متوقف کردن سرورها و آزادسازی پورت‌ها
runrepo stop
```

### ۹. دستورات `runrepo tree` و `runrepo cache` — مونوریپو و مدیریت کش

```bash
# نمایش بصری توپولوژی زیرپروژه‌های یک مونوریپو
runrepo tree ./my-monorepo

# مدیریت و پاکسازی مخازن کلون‌شده در کش
runrepo cache list
runrepo cache clean --all
```

## 🔧 ویژگی‌های پیشرفته و خودترمیمی (Self-Healing)

### ۱. تاب‌آوری چندسکویی و پشتیبان‌های کانتینری
- **سازگاری با داکر در حالت ویندوز**: هنگامی که داکر در ویندوز بدون پشتیبانی از ایمیج‌های لینوکسی اجرا می‌شود، RunRepo بدون کرش کردن، پروژه را به سمت استفاده از دیتابیس‌های لوکال یا SQLite هدایت می‌کند.
- **پشتیبانی از Yarn Berry و فضاهای کاری مدرن**: تزریق خودکار متغیر `YARN_ENABLE_SCRIPTS=0` و فلگ `--mode=skip-build` برای جلوگیری از خطای Call Stack Overflow در اسکریپت‌های پس از نصب.
- **حل تعارضات سخت وابستگی‌های npm (`ERESOLVE`)**: فال‌بک زنجیره‌ای هوشمند از `--legacy-peer-deps` به `--force` برای نصب موفق پکیج‌های ناسازگار با npm مدرن.
- **پشتیبانی از افزونه‌های باینری C در پایتون**: در صورت شکست ساخت اکستنشن‌های C در پایتون ۳.۱۴ روی ویندوزهای بدون کامپایلر MSVC، سیستم خودکار محیط را با پایتون ۳.۱۲ و ویل‌های باینری آماده پیکربندی می‌کند.

### ۲. ابزارهای بدون نیاز به نصب (Zero-Install Shims)
سیستم به کمک شیم‌های پویا (`uvx poetry`, `uvx pipenv`, `npx -y pnpm`, `npx -y yarn`) ابزارهای موردنیاز را بدون نیاز به نصب سراسری روی سیستم‌عامل کاربر در لحظه اجرا می‌کند.

## 🔒 تکرارپذیری قطعی (`runrepo.yaml` و `runrepo.lock`)

RunRepo اجرای قطعی، بدون تغییر و یکسان پروژه‌ها را روی سیستم‌های مختلف و CI تضمین می‌کند.

### بازنویسی‌های صریح (`runrepo.yaml`)

```yaml
version: 1
project:
  name: "my-web-app"
  entrypoint: "src/index.ts"

environment:
  node: ">=20.0.0"
  services:
    - name: postgres
      version: "16-alpine"
      port: 5432

scripts:
  install: "pnpm install --frozen-lockfile"
  start: "pnpm dev"
```

### فایل قفل قطعی (`runrepo.lock`)

پس از راه‌اندازی موفقیت‌آمیز پروژه، فایل قفل ساختاریافته و بدون کلیدهای محرمانه تولید می‌شود:

```yaml
# Generated by RunRepo v1.0.0 - DO NOT EDIT MANUALLY
version: 1
generated_at: "2026-08-19T12:00:00Z"
project:
  name: "my-web-app"
runtimes:
  node: "22.14.0"
package_managers:
  pnpm: "10.4.0"
services:
  - name: postgres
    image: "postgres:16-alpine"
    port: 5432
```

## 🛡️ مدل امنیت و ایزولاسیون (Sandboxing)

RunRepo لایه‌های حفاظتی متعددی برای ایمنی سیستم میزبان فراهم می‌کند:

۱. **محدودیت محدوده فایل‌سیستم**: دستورات تنها در پوشه همان مخزن اجازه اجرا دارند (`SandboxPolicy`) و تلاش برای خروج از پوشه (`../../`) بلاک می‌شود.  
۲. **مسدودسازی دستورات مخرب**: دستورات منطبق بر الگوهای خطرناک نظیر `rm -rf /`، `format`، `drop database` و `mkfs` شناسایی و مسدود می‌شوند.  
۳. **پنهان‌سازی اطلاعات حساس**: تمام توکن‌ها، رمزها و API Keyها در لاگ‌ها به شکل `[REDACTED]` نمایش داده می‌شوند.  
۴. **ادغام غیرمخرب فایل‌های `.env`**: فایل‌های `.env` موجود رونویسی نمی‌شوند، مقادیر جدید به شکل امن ادغام شده و بکاپ لحظه‌ای ساخته می‌شود.

## 🔍 موتور عیب‌یابی و رفع تداخل پورت‌ها

هنگامی که اجرای یک برنامه یا دیتابیس با مشکل مواجه می‌شود، موتور عیب‌یابی به صورت خودکار عمل می‌کند:

۱. **بررسی سوکت‌های شبکه**: از طریق ابزارهایی مانند `netstat -ano` یا `lsof` پردازه‌ای که پورت را اشغال کرده شناسایی می‌کند.  
۲. **یافتن پورت آزاد بعدی**: به صورت خودکار پورت جایگزین بعدی (`5433`، `5434` و ...) را یافته و در فایل تنظیمات اعمال می‌کند.  
۳. **پیشنهادات اصلاحی مشخص**: دستورات ترمینال لازم برای متوقف‌سازی پروسه مزاحم را به کاربر نمایش می‌دهد.

## 🤖 یکپارچگی اختیاری با هوش مصنوعی جمینای (Gemini AI)

برای پروژه‌هایی با ساختار بسیار خاص یا خطاهای پیچیده، امکان فعال‌سازی هوش مصنوعی Google Gemini وجود دارد:

```bash
# فعال‌سازی هوش مصنوعی با تنظیم کلید API
export GEMINI_API_KEY="your-api-key"
runrepo setup https://github.com/owner/project
```

- **خروجی ساختاریافته**: پاسخ‌ها توسط اسکیماهای سخت‌گیرانه Pydantic اعتبارسنجی می‌شوند.  
- **فیلتر امنیتی**: هرگونه پیشنهاد دستورات مخرب توسط هوش مصنوعی رد صلاحیت می‌شود.  
- **بدون وابستگی سنگین**: ارتباط به صورت مستقیم با APIهای REST جمینای انجام می‌شود.
